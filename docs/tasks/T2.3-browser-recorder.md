## Goal

On Page 1 the user can press Record, speak, press Stop (or hit the 5-minute limit) and see the transcript appended to the textarea. Microphone, upload and STT failures show a clear message and keep the recording so it can be downloaded or re-sent.

## Acceptance criteria

- [ ] Reducer states: `idle → requesting → recording → transcribing → idle`, plus `error`. Unit tests cover every transition, including stop during `requesting`, a second start while busy (ignored), tick/elapsed time, and a retry from `error`.
- [ ] Record asks for the microphone; the `MediaRecorder` mime type is the first supported of `audio/webm;codecs=opus`, `audio/webm`, `audio/ogg;codecs=opus`. Only types the API accepts (webm, ogg, wav, mpeg) are used, so `audio/mp4` is never chosen; no supported type → the "not supported" error.
- [ ] A timer shows `m:ss` while recording; at 5:00 recording stops automatically and the audio is transcribed as on a manual Stop.
- [ ] After Stop, the blob is uploaded as multipart field `audio` with the right file name and content type; the returned text is **appended** to the textarea (separated by a space or newline from existing text, no leading separator when empty); the textarea stays editable throughout.
- [ ] Silence (API returns `text: ""`) appends nothing and shows "No speech was detected" instead of an error.
- [ ] Error messages (each its own test): permission denied, no microphone, `MediaRecorder` or `getUserMedia` unsupported, recorder error mid-recording, API errors by `code` (`stt_unavailable`, `stt_timeout`, `payload_too_large`, `validation`, `network_error`, `unexpected_response`). The microphone stream is always released (tracks stopped) on stop, error and unmount.
- [ ] After an upload/STT error the recording is kept: "Download recording" and "Try again" (re-send the same blob) are available. Download is a client-side Blob download with a timestamped file name and the right extension; it is also available after a successful transcription until the next recording replaces it.
- [ ] Generate and Record are not usable at the same time as is sensible: Record is disabled while generating or transcribing; Generate is disabled while recording or transcribing.
- [ ] Leaving the page or unmounting during a recording or upload stops the stream and aborts the request without errors or state updates after unmount.
- [ ] No transcript or audio content is logged to the console.
- [ ] `npm test`, `npm run lint`, `npm run build` pass; `node scripts/check.mjs --all` passes; default `dotnet test` still passes offline.

## Notes

- API contract for this task (status.md, T2.2): `POST /api/transcriptions`, field `audio`, 25 MB, webm/ogg/wav/mpeg; `{ text, durationMs }`; errors 400 `validation`, 413 `payload_too_large`, 415 `unsupported_media_type`, 503 `stt_unavailable`, 504 `stt_timeout`. The server accepts content-type parameters, so `audio/webm;codecs=opus` can be sent as is.
- A 5-minute opus recording is far below 25 MB; the 413 message is still handled.
- `getUserMedia` needs a secure context: `http://localhost` works; the Docker demo on `localhost:5080` works too. Another host name over plain HTTP does not (put this in the README).
- Transcripts may be lowercase without punctuation (T2.1); the client does no clean-up.
- ⚠ VERIFY: `MediaRecorder.isTypeSupported` list and the mime type Chrome/Edge actually produce (plan section 9) — check against current MDN, record in Decisions.
- jsdom has no `MediaRecorder` or `getUserMedia`: tests use small hand-written fakes (no new mocking library).
- Windows: a stopped `npm run dev` can leave `node.exe` locking `node_modules`; check the port before the review step.

### Decisions

- Mime types tried in order: `audio/webm;codecs=opus`, `audio/webm`, `audio/ogg;codecs=opus`, `audio/ogg`. `audio/mp4` is never chosen (the API rejects it), so Safari gets the "not supported" message. The upload carries the recorder's own `mimeType` (falls back to the requested one); the server accepts codec parameters.
- ⚠ VERIFY MediaRecorder types: MDN's `isTypeSupported` page confirms codec strings such as `audio/webm;codecs=opus` are valid input; it does not give a per-browser table, and the WebFetch summary of it was not authoritative. Chrome/Edge producing webm/opus is therefore **not verified from docs**; the human's manual check covers it. The code does not depend on it: it asks `isTypeSupported` at run time.
- Timer counts one-second interval ticks (no clock reads); the limit is `maxRecordingSeconds` = 300 and the auto-stop calls the same `recorder.stop()` as the button.
- `useRecorder` keeps a ref of the status so two quick clicks cannot start two recordings, and an attempt counter so a late microphone grant after Cancel (or after a restart) is released, not used.
- A recorder error mid-recording fails the recording and keeps no audio (nothing reliable to keep); upload errors keep the blob.
- The kept recording is replaced when the next recording finishes (a failed start keeps the old one). Download stays available after success.
- `api.ts`: `generateTicket` and the new `transcribeAudio` share a private `send` helper (same error mapping, no behaviour change; existing tests unchanged and green).
- Text typed during transcription is preserved: the page appends to the latest transcript through a ref.
- Found in the human's manual check (2026-11-10): on silence the STT returned `"."`, not `""`, so a dot was appended. The recorder now treats a transcript with no letter or digit (`/[\p{L}\p{N}]/u`) as silence. The API is unchanged (T2.2 passes `text` through). Other silence hallucinations that contain words (such as "you" or "Thank you.") cannot be filtered reliably and are not handled; T2.4 should note how often they occur.
- No new dependency.
