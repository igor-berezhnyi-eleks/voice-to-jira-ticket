### Decisions
- ⚠ VERIFY xUnit v3 template: `dotnet new list xunit` (2026-11-05) shows only the v2 `xunit` template. Instead of installing templates, the test csproj is hand-written with xUnit v3 packages (no template needed). Versions from `dotnet package search --exact-match` on 2026-11-05: xunit.v3 4.0.2, xunit.runner.visualstudio 4.0.1, Microsoft.NET.Test.Sdk 18.11.0, Microsoft.AspNetCore.Mvc.Testing 10.0.14.
- xunit.v3 4.x defaults to Microsoft.Testing.Platform, and on the .NET 10 SDK `dotnet test` then fails ("Testing with VSTest target is no longer supported…"). Set `IsTestingPlatformApplication=false` and `UseMicrosoftTestingPlatformRunner=false` so tests run through VSTest; this keeps the `--filter "Category!=…"` syntax used by `scripts/check.mjs` and CLAUDE.md. Alternative (opt into MTP in `global.json`) would change the filter syntax everywhere: not done.
- `global.json` pins 10.0.403 (latest installed SDK; 10.0.401 also installed), `rollForward: latestFeature`.
- New dependency `Microsoft.AspNetCore.OpenApi` 10.0.14: built-in OpenAPI document generation (plan 4.4).
- New dependency `Swashbuckle.AspNetCore.SwaggerUI` 10.3.1: only the static UI, pointed at `/openapi/v1.json`; smallest option, no second document generator (the full Swashbuckle package would duplicate `Microsoft.AspNetCore.OpenApi`).
- Error-code mechanism: `ApiException(statusCode, code, title, detail?)`; `Message` is for logs only, `Detail` is client-safe. Codes as constants in `ErrorCodes` (only `internal_error` and `validation` for now; later tasks add theirs).
- `UseStatusCodePages()` so framework 404/405 also return ProblemDetails (without `code`; only exceptions carry it).
- launchSettings `http` profile on http://localhost:5080 (same port as the planned Docker URL; do not run both at once).
