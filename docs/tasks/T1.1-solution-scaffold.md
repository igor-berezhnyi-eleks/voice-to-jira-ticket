## Goal

An empty but well-formed .NET 10 solution: one API project with a health endpoint, consistent error responses and OpenAPI, plus a test project with passing integration tests.

## Files

- `VoiceToTicket.slnx`
- `global.json` (pin the installed 10.0 SDK, `rollForward: latestFeature`)
- `Directory.Build.props`
- `src/VoiceToTicket.Api/**` (`VoiceToTicket.Api.csproj`, `Program.cs`, `Properties/launchSettings.json`, `appsettings.json`, `appsettings.Development.json`, `Features/Health/**`, `Infrastructure/**`)
- `tests/VoiceToTicket.Api.Tests/**`

## Out of scope

- Any ticket, transcription or Claude code. Docker. The web app. Static file serving.
- Libraries ruled out by D2/D12 (MediatR, FluentValidation, Moq, FluentAssertions, …).

## Acceptance criteria

- [ ] `Directory.Build.props` sets `net10.0`, nullable, implicit usings and `TreatWarningsAsErrors`.
- [ ] `GET /health` returns 200 `{"status":"ok"}`; covered by an integration test using `WebApplicationFactory<Program>`.
- [ ] One `IExceptionHandler` turns unhandled exceptions into a 500 ProblemDetails with `code: "internal_error"` and no exception message or stack trace in the body; covered by a unit test of the handler.
- [ ] A small error-code mechanism exists for later tasks to use (e.g. an exception type carrying an HTTP status and `code`), and the handler maps it; covered by a unit test.
- [ ] OpenAPI document served at `/openapi/v1.json`; Swagger UI at `/swagger` **only** in Development (integration test: not available in Production environment).
- [ ] `Program.cs` contains composition only (service registration, middleware, endpoint mapping calls); endpoints live in their feature folder.
- [ ] `dotnet build` produces 0 warnings; `dotnet test` passes.
