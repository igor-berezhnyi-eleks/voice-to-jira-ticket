### Decisions

- ⚠ VERIFY image tags, 2026-11-05. `mcr.microsoft.com/dotnet/sdk:10.0.403` and `mcr.microsoft.com/dotnet/aspnet:10.0.14`: latest 10.0 releases per the MCR tag lists and `dotnet/core` `release-notes/10.0/releases.json`; the SDK matches `global.json`. `node:24.21.0-alpine`: exists on Docker Hub and matches the local Node used for T1.4; 24.x is the version the web lock file was tested on, so newer Node releases were not adopted here. The lock file includes the `@rolldown/binding-linux-x64-musl` binding that Alpine needs.
- CI action versions, from each repository's latest GitHub release, 2026-11-05: `actions/checkout@v7`, `actions/setup-dotnet@v6`, `actions/setup-node@v7`.
- SPA files reach the image by copying `web/dist` to `wwwroot` in the final stage, so no csproj change.
- SPA serving is a small check in `Program.cs` after `UseRouting`, not `MapFallbackToFile`: if no endpoint matched, the request is GET or HEAD, the path is outside `/api` and `/health` and has no file extension, it is rewritten to `/index.html`. The first version used `MapFallbackToFile` with a regex and changed API answers: `GET /api/tickets` became 404 instead of 405 (confirmed by temporarily removing the fallback), and `POST /api/unknown` became 405 instead of 404 (found by the reviewer; it breaks the criterion). With no fallback endpoint, routing behaves as it did before this task, so both are back to normal and the wider test theories pin them.
- `/swagger` in the container returns the SPA, because Swagger UI is Development-only and that path is then a client path.
- `.env` is optional in compose (`required: false`), so the quick start works with no file. Config names follow plan 4.6.
