## Goal

`docker compose up --build` starts the app at http://localhost:5080 with the API serving the built SPA, and the paste → fake ticket flow works in the container.

## Files

- `src/VoiceToTicket.Api/Dockerfile`, `.dockerignore`
- `docker-compose.yml`
- `.env.example`
- `src/VoiceToTicket.Api/Program.cs` (static files + SPA fallback only)
- `tests/VoiceToTicket.Api.Tests/**` (fallback test)
- `README.md`
- `.github/workflows/ci.yml`

## Out of scope

- The `stt` service (T2.1). GPU override. Any production hardening.

## Acceptance criteria

- [ ] Multi-stage Dockerfile: Node stage builds `web/`, .NET SDK stage publishes the API, runtime stage uses the ASP.NET image and contains the SPA in `wwwroot`. Image tags pinned to exact versions (⚠ VERIFY current tags).
- [ ] `docker-compose.yml` has the `api` service on host port 5080, reads secrets from `.env` (git-ignored); `.env.example` lists every variable with a placeholder.
- [ ] The API serves `index.html` for unknown non-API paths, but `/api/*` and `/health` unknown routes still return 404 (integration test).
- [ ] `docker compose up --build` → `GET http://localhost:5080/health` returns ok and the SPA loads; paste → fake ticket works.
- [ ] `README.md`: prerequisites, quick start (Docker and development), configuration table, link to the plan.
- [ ] `.github/workflows/ci.yml` runs `dotnet build`, `dotnet test`, and the web build/test/lint on push and pull request (cannot be verified until the branch is pushed — record as not verified).
- [ ] `dotnet test` and `node scripts/check.mjs --all` pass.
