## Goal

`POST /api/transcriptions` accepts one recorded audio file, sends it to the Speaches container through `ISpeechToText`/`SpeachesClient`, and returns `{ text, durationMs }`. Size, type and STT failures map to ProblemDetails with the documented `code`.

## Acceptance criteria

- [ ] `ISpeechToText.TranscribeAsync(Stream, string fileName, string contentType, CancellationToken)` returns `Transcription(string Text, long DurationMs)`.
- [ ] `SpeachesClient` uses a named `HttpClient` from `IHttpClientFactory`, posts multipart to `{BaseUrl}/v1/audio/transcriptions` with `file`, `model`, `language`, `response_format=json`; reads `{"text": ...}`; no retry; timeout from `Stt:TimeoutSeconds`.
- [ ] `Stt` options (`BaseUrl`, `Model`, `Language`, `TimeoutSeconds`) bound with `IOptions<T>` and `ValidateOnStart`; defaults match plan 4.5 and the model pinned in T2.1.
- [ ] `POST /api/transcriptions` (multipart, field `audio`) returns `200 { text, durationMs }` for `audio/webm`, `audio/ogg`, `audio/wav`, `audio/mpeg`.
- [ ] 400 `validation` for a missing field, empty file, or unsupported content type; 413 `payload_too_large` above 25 MB (including when the multipart body is larger than the limit); content type parameters such as `audio/webm;codecs=opus` are accepted.
- [ ] STT unreachable or non-success response → 503 `stt_unavailable`; STT timeout → 504 `stt_timeout`; a caller cancelling the request is not reported as a timeout.
- [ ] Response without usable `text` (missing field, invalid JSON) → 503 `stt_unavailable` with no transcript in the log or error detail.
- [ ] Empty transcript from STT (silence) returns 200 with `text: ""` (decide and log in Decisions; T2.3 shows a message).
- [ ] Transcript text never logged at Information or above; a test or review check covers it.
- [ ] `Category=Stt` smoke test: skips unless `VTT_RUN_STT=1`; posts a fixture from `tests/fixtures/audio/` to the running container and asserts its key words.
- [ ] Default `dotnet test` passes offline; `node scripts/check.mjs --all` passes.

### Decisions

- Silence returns 200 with `text: ""` (criterion decision); the client trims the text.
- A body that is not `multipart/form-data` returns 415 `unsupported_media_type` (from `.Accepts<>`), not 400 as the criterion implied. It uses an existing code and says what is wrong.
- Content types are matched case-insensitively and forwarded lowercase without parameters (`audio/webm;codecs=opus` → `audio/webm`).
- 25 MB is checked on the uploaded file (413 with a detail); Kestrel's default body limit (about 28.6 MB) rejects larger bodies earlier through the existing `BadHttpRequestException` mapping. Both answered 413 `payload_too_large` on a real server.
- `DisableAntiforgery()` on the endpoint: required for form binding, and the API has no cookies or sessions.
- `HttpClient.Timeout` is infinite; `SpeachesClient` enforces `Stt:TimeoutSeconds` with a linked token source on `TimeProvider`, so caller cancellation is not reported as a timeout.
- `compose`: `api` `depends_on: stt` with `service_started`, not healthy (cold download is minutes). `Stt__BaseUrl` is not set in compose because `appsettings.json` already defaults to `http://stt:8000`; no change was needed there.
- No new dependency.
