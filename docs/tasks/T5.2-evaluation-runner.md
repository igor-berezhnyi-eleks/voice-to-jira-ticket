## Goal

A runner in `tests/VoiceToTicket.Evaluation` that generates a ticket for every frozen scenario with each configured model, applies the automatic checks of plan 7.2, and writes `eval/results/<yyyyMMdd-HHmm>/<model>.json` plus a `scoring-sheet.md` for the human to fill in (T5.4).

## Proposals (answer or say "all as proposed")

1. **Shape.** An xUnit test project with a single `[Trait("Category","Evaluation")]` entry test that skips unless `VTT_RUN_EVALUATION=1`. The runner logic itself (loading, checks, writers) is plain classes with offline unit tests, so the default `dotnet test` still covers it. Alternative: a console app. Proposed: test project, as the plan says "Category=Evaluation".
2. **Generator under test.** The runner takes an `ITicketGenerator` per model. Real runs build `ClaudeTicketGenerator` with `Claude:Model` set per model (default `claude-sonnet-5-5`, `claude-haiku-5-5`; override with `VTT_EVAL_MODELS`, comma-separated) and the key from the same configuration the API uses (user-secrets / env), never read from a file in `eval/`. The "fake" acceptance run uses `FakeTicketGenerator` and is a normal offline test.
3. **Results in git.** `eval/results/` is committed (results are the evidence for the report), except a run is only committed on the human's say-so. Alternative: git-ignore it and copy the chosen run into `docs/`. Proposed: commit.
4. **Repeats.** Each scenario once; AMBIGUOUS-01, NOISY-01 and MIXED-01 run 3 times in total (1 + 2 extra? or 1 + 3?). The plan says "plus 3 repeats". Proposed: **1 + 3 = 4 runs** for those three, 10 + 9 = 19 calls per model.
5. **Sequential, no retries.** Calls run one at a time (clear latency numbers, no rate-limit surprises). A generator error (`llm_*`, validation) is recorded as a failed row with its code, not retried, consistent with D15.
6. **Cost.** Token counts are recorded per ticket from `Usage`; cost in USD is computed only if the current prices are put in a small `eval/pricing.json` that the human confirms. Proposed: record tokens only and add cost in T5.4 from the report's price table.
7. **Trap check.** Case-insensitive substring search over the ticket serialized as JSON (plan 7.1), so a trap in any field counts, including `missingInformation` questions. Alternative: exclude `missingInformation` (a question "Which browser?" would hit the trap "Chrome" only if the model names it). Proposed: search everything, and list in the scoring sheet where the hit was so the human can discount a question that merely mentions a term.

## Acceptance criteria

- [ ] The project loads all scenario files from `eval/scenarios/` and rejects a file that is invalid or whose `id` differs from its file name, with a message naming the file.
- [ ] For each model and scenario the runner calls the generator and records: scenario id, run number, ticket (or error code), type, `type == expectedType` (null for AMBIGUOUS-01 and MIXED-01, which are excluded from type accuracy), validator result and error list, trap hits (text and field), duration, token usage.
- [ ] AMBIGUOUS-01, NOISY-01 and MIXED-01 are repeated as decided in proposal 4; stability (same type across all runs, any trap hit in any run) is computed per scenario.
- [ ] `eval/results/<yyyyMMdd-HHmm>/<model>.json` is well-formed and carries the run metadata: model, provider, start time (from `TimeProvider`), git commit, prompt hash (hash of `TicketPrompt.System`), scenario tag/version.
- [ ] `scoring-sheet.md` lists every ticket next to its script, facts, expected missing items and traps, with empty fields for the human scoring of plan 7.3 (facts x of n, missing flagged x of n, spurious, invention, usability).
- [ ] A run against `FakeTicketGenerator` produces well-formed output end to end, offline, in the default `dotnet test`.
- [ ] The Evaluation entry test is skipped without `VTT_RUN_EVALUATION=1` and does not need a key to be skipped; the default `dotnet test` stays offline and green.
- [ ] A failing generator call (exception with an error code) is recorded and the run continues.
- [ ] No transcript text is logged at Information or above.
