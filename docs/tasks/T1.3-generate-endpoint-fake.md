### Decisions

- ⚠ VERIFY `AddValidation()` (.NET 10, SDK build in this repo), from [ASP.NET Core 10 release notes](https://learn.microsoft.com/en-us/aspnet/core/release-notes/aspnetcore-10.0?view=aspnetcore-10.0) and the [Minimal APIs page](https://learn.microsoft.com/en-us/aspnet/core/fundamentals/minimal-apis?view=aspnetcore-10.0), then confirmed by the integration tests: records with attributes on positional parameters work. No csproj property was needed (the docs do not mention one; the tests prove the filter runs). Errors go through `IProblemDetailsService`, so the existing `CustomizeProblemDetails` adds `code: "validation"` with no new mapping.
- Observed error shape: `{ type, title, status: 400, errors: { "Transcript": ["…"] }, traceId, code: "validation" }`. The key in `errors` is the C# member name (`Transcript`), not the JSON name (`transcript`). Left as the framework returns it: no criterion sets the casing and a remap would be custom code. The test pins it, so a change is noticed. T1.4 should not depend on matching the key to the JSON field.
- Whitespace-only transcripts are rejected: `[Required]` treats them as empty. Beyond the literal "20–20,000 characters", and uses only the built-in attribute. Padding still counts toward the 20 minimum (`"a"` + 19 spaces passes), as the plan counts characters.
- `TicketGenerator:Provider` is a string checked with `.Validate(...)`, not an enum, so the startup error is our own message (`TicketGenerator:Provider must be 'Fake'.`). No default: absent or empty fails startup (D9 "explicit config"), and `appsettings.json` sets `Fake`.
- Plan 4.6 vs rule 2: the fake's description cannot be `"Not provided"`, so it is the trimmed transcript. Transcripts that would produce an invalid title or description (only punctuation, or exactly `Not provided`) use fixed fallback texts, so every fake ticket passes the validator.
- Enums in HTTP JSON: `ConfigureHttpJsonOptions` adds `JsonStringEnumConverter<TicketType>`, because the default would send `type` as a number. Request and response use the framework's options; the ticket is read back with the strict `TicketJson.Options` in tests.
- Logger category: `ILogger<GenerateTicketRequest>`, because a static endpoint class cannot be a type argument.
- No new dependencies. Files stay inside the task's list. `ApiFactory` is unchanged; tests use `WithWebHostBuilder`.
