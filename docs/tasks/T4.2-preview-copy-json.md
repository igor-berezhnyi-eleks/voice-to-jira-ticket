## Acceptance criteria

- [ ] `editedTicket` returns a ticket in contract shape from the edits: blank list rows are dropped, row ids are gone, blank text becomes exactly `Not provided`, `missingInformation` is the generator's list unchanged, and only the object for the ticket's type carries content (the other is as received).
- [ ] `plain.ts` renders title, type, description and the type's fields (numbered steps / bullets for lists), with no missing-information section; a `Not provided` string and an empty list both appear as the text `Not provided`.
- [ ] `jiraWiki.ts` renders the same content as Jira wiki markup: `h1.`/`h2.` headings, `#` numbered steps, `*` bullets, no missing-information section; user text is not escaped.
- [ ] The preview shows the selected format, defaults to Plain, updates as fields are edited, and switching the toggle changes only the preview. It always has the raw text in a read-only textarea (what Copy copies); in Jira wiki mode a rendered view (`JiraWikiView`) is shown beside it, labelled as an approximation of how Jira shows it.
- [ ] `JiraWikiView` renders `h1.`/`h2.` as headings, `#` lines as an ordered list, `*` lines as a bullet list, other lines as paragraphs, and never injects HTML (text such as `<b>` stays literal).
- [ ] Copy writes exactly the previewed text to the clipboard and shows "Copied" for about two seconds; if the clipboard is unavailable or rejects, it shows a visible failure message and the preview stays selectable.
- [ ] Save as JSON downloads `ticket-<type>-<yyyyMMdd-HHmmss>.json` (type in lower case, local time) containing the edited ticket in contract shape, pretty-printed with 2 spaces.
- [ ] "Connect to Jira board" is visible, disabled, with the tooltip "Not part of the PoC (P2)".
- [ ] Snapshot tests for a Bug and a Feature in both formats, each including a "Not provided" field and an empty list. `npm test`, `npm run lint` and `npm run build` pass.

## Original questions (for reference)

1. **Missing information in the copy:** plan 4.6/6 puts a missing-information section in the Jira text. Proposal: include it in both formats, listing every question the generator raised (even if you have since filled that field), as a "Missing information" section at the end. Alternative: leave out questions whose field now has content. Include all?
2. **Gaps in the output:** proposal is to print `Not provided` for a blank field or empty list (so the pasted ticket shows the gap explicitly and a developer can search for it), not to omit the section. OK?
3. **Jira wiki escaping:** user text can contain `*`, `_`, `{`, `[`, a leading `#`, `*` or `-`, or `h1.`. Proposal: backslash-escape `{ } [ ] | *` `_` and a leading list or heading marker in each line, minimal and tested; the text then reads literally in Jira. A bug description such as `NullReference in {Foo}` would not turn into a macro. Or leave user text unescaped (simpler; paste may mis-render)?
4. **Multi-line text:** descriptions and results may contain line breaks. Proposal: keep them as they are in both formats; in a numbered or bullet item, a line break stays inside the item (wiki: `\\` is not added; Jira 7 renders a single newline as a line break). OK?
5. **Copy and Save unavailable cases:** proposal: if `navigator.clipboard` is missing or rejects, show "Copy failed. Select the text above and copy it yourself" (no `execCommand` fallback). The preview is a read-only textarea so it can be selected. OK?
6. **Preview widget:** a read-only `<textarea>` (selectable, monospace) rather than a rendered HTML approximation of the wiki. The wiki view is the raw markup, which is what gets pasted. OK?

## Log

### Plan

Tests first for the pure modules, then the page. `editedTicket(base, texts, lists)` builds the contract-shaped ticket (trim, blank text → `Not provided`, blank list items dropped; lists only need `{text}` so row ids never leave the page). `plain.ts` and `jiraWiki.ts` share a small `sections(ticket)` view of the fields via `fieldsFor` labels, and differ only in headings and list markers. `jsonFileName(ticket, date)` uses local time. `JiraWikiView` parses wiki lines into headings, ordered and bullet lists, and paragraphs, and renders React elements. `TicketPage` derives the edited ticket on each render, shows the preview in a read-only textarea (label "Preview"), plus the wiki view in Jira mode, Copy with a two-second "Copied" or a failure message, Save as JSON via a Blob download, and the disabled Jira button. No ⚠ VERIFY facts.

### Decisions

- `ticketSections` (field labels, order, gaps normalised) lives in `editedTicket.ts`, shared by both renderers, to avoid a file outside the list.
- Preview is a read-only textarea labelled "Preview" (always the raw text that Copy writes); in Jira wiki mode `JiraWikiView` is shown below it. Wiki `h1`/`h2` are shown as `h3`/`h4` since the page has its own `h1`/`h2`. Inline wiki markup (bold etc.) is not rendered; the renderer writes none.
- Type is printed as a plain `Type: Bug` line under the title in both formats.
- A failed copy message stays about six seconds (three times the "Copied" time) so it can be read.
- Save as JSON calls `downloadText` (Blob + anchor); tests mock it, so the real download is only covered by the manual check.
- No new dependencies.
