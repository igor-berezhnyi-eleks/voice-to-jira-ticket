# T1.4 — Web scaffold and both pages (read-only ticket)

- **Milestone:** M1 Walking skeleton
- **Status:** done
- **Depends on:** T1.3
- **Plan sections:** 3 (D3, D8, D9), 4.2 (`web/`), 4.8 (structure only), 4.9 (development)
- **Parallel-safe with:** T2.1

## Goal

A React + Vite + TypeScript app where the user pastes or types a transcript on Page 1, presses Generate, and sees the ticket's fields (read-only) on Page 2, using generated TypeScript types for the contract.

## Files

- `web/**` (except `web/src/contract.ts`, which is only written by `npm run gen:contract`)

## Out of scope

- Recording (T2.3), editing fields, preview, copy, JSON download (M4). Styling beyond plain readable CSS. Router, state library, UI kit (D3).

## Acceptance criteria

- [x] Vite + React + TypeScript (`strict`), with `npm` scripts: `dev`, `build`, `test` (Vitest, single run), `lint` (ESLint), `gen:contract` (json-schema-to-typescript from `../contract/ticket.schema.json` to `src/contract.ts`).
- [x] Vite dev server proxies `/api` and `/health` to the API (`http://localhost:5xxx` from launchSettings; document the port in the log).
- [x] `src/api.ts`: `generateTicket(transcript, signal)` returns the typed response or throws a typed error carrying ProblemDetails `code`; unit-tested with a mocked `fetch` (success, 400 validation, network failure).
- [x] Page 1: textarea, Generate button disabled under 20 characters or while a request runs, error message on failure, transcript kept on error.
- [x] Page 2: type badge and all fields of the ticket's type shown read-only; `"Not provided"` values visible as such; missing-information list; Back button returns to Page 1 with the transcript intact.
- [x] Banner "Fake generator active — tickets are not real" when `provider === "Fake"`.
- [x] `npm run build`, `npm test` and `npm run lint` pass; `node scripts/check.mjs` passes.

### Notes for the study

- Human input: two decisions, no corrections. The agent stopped to ask about the npm registry (a global client feed returning E401) instead of overriding it, and the human chose the public registry. The human also kept the banner as built.
- `node scripts/check.mjs` before the commit passed: npm build, test and lint.
- The reviewer's `npm ci` deleted most of `web/node_modules` and then failed with EPERM, twice, because the agent's own Vite server was still running and held a native file open. Cause: stopping the background `npm run dev` shell did not stop its `node.exe` child on Windows, and `curl` to port 5080 was checked but port 5173 was not. Repaired by stopping that one PID and running `npm ci`. No tracked files were affected.
- Two harness gaps this shows: an agent check should confirm the ports are free before review, and a reviewer that runs a destructive install in the shared tree can break the work it is reviewing. The reviewer worked around it by checking on a scratch copy and reported the damage first, without being asked.
- The reviewer's first two `npm ci` runs did not use `--offline`, so they may have reached the registry despite its no-network rule.
- The reviewer tested its findings with mutations. That exposed a test whose name claimed more than it checked: it passed with `setError(null)` removed, because the page unmounts on success. A test written first by the implementer still needed an independent check.
- A permission classifier denied a broad PowerShell process listing for both the agent and the reviewer. A narrower lookup by port (`netstat`, then `tasklist` for that PID) was allowed and enough to identify the process before stopping it.
