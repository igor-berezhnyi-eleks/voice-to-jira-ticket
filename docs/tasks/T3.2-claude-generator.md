## Goal

With `TicketGenerator:Provider = Claude` and an API key, `POST /api/tickets` sends the transcript to Claude with `TicketPrompt` and the contract's JSON schema, and returns a validated ticket. Every failure maps to its `llm_*` error code. With `Provider = Fake` nothing changes.

- Files changed beyond the task's list (all needed): `tests/VoiceToTicket.Api.Tests/ApiFactory.cs` (test isolation), `tests/.../Tickets/TicketGeneratorOptionsTests.cs` (message and `Claude` now valid, lower-case `claude` still invalid), `src/.../appsettings.json` (Claude section, no key), `.env.example` (comment). `docker-compose.yml` unchanged: `env_file: .env` already passes the variables.

- `UserSecretsId` added to the csproj by `dotnet user-secrets init` (human). The csproj was re-formatted (BOM and squeezed `PropertyGroup` removed); content unchanged.
- ⚠ VERIFY, confirmed by one real call on 2026-11-10 (`Category=Live`, passed in 5 s) and the SDK's XML docs:
  - model `claude-sonnet-5-5` accepted; source: the `claude-api` skill's model table and the live call.
  - the exported ticket schema (nullable `bug`/`feature` as type arrays, `additionalProperties: false`, no `maxLength`) is accepted by structured outputs via `BetaOutputConfig.Format = BetaJsonOutputFormat { Schema }`. This closes the T1.2 caveat "not yet by a real API call".
  - `Effort` in `BetaOutputConfig` (`medium`); `Thinking = BetaThinkingConfigAdaptive`; no `temperature`, `top_p`, `top_k`, `budget_tokens`.
  - refusal fallback: beta `server-side-fallback-2026-07-01` with `Fallbacks = new BetaFallbacksParam(new Default())`, sent for `claude-sonnet-5-5` and `claude-opus-5-5` only (D7); accepted by the API. A real refusal path was **not** exercised.
  - stop reason: `response.StopReason.Raw()` gives the wire string (`end_turn`, `refusal`, `max_tokens`); the parser accepts `end_turn` only and treats any other unknown value as `llm_invalid_output`.
  - SDK exceptions: `AnthropicException` is the base of all status and I/O exceptions (pinned by a hierarchy test). 401/403/404/429/5xx/connection errors all map to `llm_unavailable` (503); the SDK retries 408/409/429/5xx/connection errors twice by itself (default `MaxRetries` 2, not changed).
  - timeout: the generator owns the deadline (`Claude:TimeoutSeconds`, linked token source); the SDK client timeout is that plus 5 s so the generator's deadline decides and maps to `llm_timeout` (504). A caller's cancellation is rethrown and never mapped.
- Beta endpoint (`client.Beta.Messages`) is used for every call because the fallback needs it; it works for models without fallback too (no beta header is sent then).
- Parser error details name rules only (validator messages, fixed strings), never the model's text; the generator logs the exception type and code at Warning, not the SDK message, because SDK messages can echo the request (which holds the transcript).
- Model returned in `GenerationResult.Model` is the configured model, not the API's echo (a fallback to another model would not show). Noted for the evaluation: if fallbacks matter, read `response.Model`.
