## Goal

Every failure a colleague can hit during a demo (STT down, microphone denied, Claude errors, oversized upload, API down) has been triggered in the real app and shows a message that says what happened and what to do, and the README lets a new person run the demo from a clean checkout.

## State found at the start

- Error code vocabulary exists and is mapped in the browser: `web/src/errorMessages.ts` (generation: `llm_refused`, `llm_invalid_output`, `llm_truncated`, `llm_unavailable`, `llm_timeout`, `network_error`, `unexpected_response`, `validation`) and `transcriptionMessage` / `microphoneMessage` in `web/src/recording/useRecorder.ts` (`stt_unavailable`, `stt_timeout`, `payload_too_large`, denied, no microphone, other microphone failure, unsupported browser). Each has a unit test; none has been checked end to end together in the real app.
- Known rough edges recorded earlier:
  - T2.3: with the API stopped, the Vite proxy's plain-text 502 shows in the recorder as "The server returned an unexpected response (HTTP 502)" (the `default` branch returns `error.message`). Logged as an optional later improvement.
  - A recording of 5 minutes is far below the 25 MB upload limit (about 1 to 2 MB as webm/opus), so the oversized-upload message cannot be reached by recording; it can only be reached by a crafted request. The transcript limit is 20,000 characters (`validation` shows the server's text).
- `README.md` exists and is partly stale:
  - The Configuration table says `Claude` is "from task T3.2" and the key "is not used until the Claude generator exists"; both are wrong since T3.2.
  - `Claude:Model`, `Effort`, `MaxTokens`, `TimeoutSeconds` are not documented; `.env.example` lists only the provider and the key.
  - No "Known limits" section, no demo script, no pointer to the evaluation (the `eval/` folder and the opt-in switches `VTT_RUN_*`, `VTT_EVAL_*`).
  - The first paragraph still says "Current progress is in docs/status.md" (fine) and has no link to a report.

## Proposals (answer or say "all as proposed")

1. **Which failures are exercised.** The matrix below. The agent triggers everything it can without a person (API and STT stopped, a crafted oversized request, an invalid key, a stale transcript); the human triggers what needs a real browser permission or microphone.

   | # | Failure | How it is triggered | Expected message (from the code today) | Who |
   |---|---|---|---|---|
   | 1 | STT container down | `docker compose stop stt`, record | "The transcription service is not available. Start it and use Try again, or download the recording." with Try again and Download | agent (UI via Playwright-driven check or the human) |
   | 2 | STT slow | set `Stt__TimeoutSeconds=1` | "Transcription took too long…" | agent |
   | 3 | Microphone denied | block the microphone for localhost in Chrome | "Microphone access was denied…" | human |
   | 4 | No microphone | disable the input device | "No microphone was found…" | human (optional) |
   | 5 | Browser without `MediaRecorder` | cannot be triggered in Chrome; covered by the unit test | "Recording is not supported…" | unit test only |
   | 6 | API down | stop the API while the page is open, press Generate and Record | generation: "Could not reach the server…" or "The server sent a reply this page does not understand…"; recorder: see proposal 3 | agent |
   | 7 | Claude key missing or rejected | `Provider=Claude`, empty or wrong key | `llm_unavailable` message, with Retry | agent (an invalid key costs nothing) |
   | 8 | Claude refusal / invalid output / truncation / timeout | cannot be triggered on demand with the real API; `Claude:TimeoutSeconds=1` gives `llm_timeout`; the others are covered by unit tests | per `errorMessages.ts` | agent (timeout), unit tests (rest) |
   | 9 | Oversized upload | crafted `curl.exe` request over 25 MB to `/api/transcriptions` | API answers 413 `payload_too_large`; the recorder's message is checked by its unit test | agent |
   | 10 | Transcript over 20,000 characters | paste a long text, press Generate | the server's `validation` text, no Retry | agent |
   | 11 | Fake banner and Claude path | `Provider=Fake` shows the banner after the first ticket | as built (D9, T1.4 decision) | human (part of the demo script) |

   The result of each row (message seen, screenshot not needed, pass or fix) goes in the Verified section of this file.
2. **How the review is done.** The agent runs the real stack (API, STT container, `npm run dev`) with the built-in browser where a permission is not needed, and reports the message text it saw for every row it can reach. Playwright e2e is not extended for this (the e2e suite forces the Fake provider and has no way to stop the STT; CLAUDE.md says check.mjs does not run e2e). Alternative: add an e2e test with a stubbed `/api/transcriptions` route returning 503. Proposed: no, the unit tests already cover the mapping; the point of this task is the real stack.
3. **Fix the proxy-502 message in the recorder.** `transcriptionMessage` gets one more case: an `unexpected_response` or `network_error` code (the server could not be reached or answered in an unknown format) shows "Could not reach the server. Start it, then use Try again, or download the recording." instead of "The server returned an unexpected response (HTTP 502)". Both keep the kept recording. A unit test covers both codes. This is the only code change planned; anything else the review finds is reported first.
4. **README structure.** Rewritten as: what it is and who it is for; prerequisites (Docker Desktop, Chrome or Edge, microphone, an Anthropic API key only for the Claude provider); quick start with Docker (fake, no key); running with Claude (`.env` with `TicketGenerator__Provider=Claude` and `Claude__ApiKey`, how to check it works); development quick start (kept); configuration table with all keys that exist (`TicketGenerator__Provider`, `Claude__ApiKey`, `Claude__Model`, `Claude__Effort`, `Claude__MaxTokens`, `Claude__TimeoutSeconds`, `Stt__*`); known limits; demo script; troubleshooting table; tests and evaluation (the switches `VTT_RUN_STT`, `VTT_RUN_LIVE`, `VTT_RUN_EVALUATION`, `VTT_EVAL_*`, with the cost warning); link to the report. The existing STT and recording sections are kept and shortened, not rewritten. Values come from `appsettings.json` and `.env.example`, checked against the code, not from memory.
5. **Known limits (facts, no verdict).** English only (`faster-whisper-medium.en`); Chrome and Edge only for recording; no Safari; recording capped at 5 minutes and 25 MB; transcript 20 to 20,000 characters; tickets are suggestions that must be reviewed; the model may leave fields "Not provided" and lists questions instead of guessing; one ticket per report; no Jira connection (copy or save as JSON); no authentication, so run it on a local machine only; the transcript is sent to the Anthropic API when `Claude` is chosen (data policy line, to be checked with the human: wording to use); the STT release candidate image and CPU speed (about 3.5 s per 10 s of audio on the reference laptop, cold start about 2.5 minutes); GPU image untested. Each limit is stated once and links to the decision or plan section that explains it.
